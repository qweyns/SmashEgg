# Что не хватает SmashEgg

Снимок по состоянию на 3.0.0 (миграция на Paper API). Пункты сгруппированы по важности; ссылки указывают на место в коде, где ограничение живёт.

## 1. Заметно пользователю прямо сейчас

| # | Чего нет | Где упирается | Что дало бы |
|---|---|---|---|
| 1 | **Per-mob и per-world настройки.** Шансы и чёрный список глобальные: нельзя «зомби ломаются в 50 %, дракон в 10 %» или «в `world_nether` свои правила» | `PluginSettings` хранит один `breakChance`/`groundChance`/`blacklist` | Самая частая просьба к таким плагинам; конфиг вида `entities.ZOMBIE.break-chance` с откатом к глобальному значению |
| 2 | **Whitelist-режим.** Есть только запрет (`black-entities`) | `PluginSettings.blacklist()` | Режим «в спавнеры можно ставить только этих мобов» |
| 3 | **Плейсхолдеры в сообщениях.** Нельзя вывести шанс, тип моба, имя игрока | `messages.*` — статические строки MiniMessage | `{chance}`, `{entity}`, `{player}`; позже — PlaceholderAPI |
| 4 | **Только чат.** Нет action bar / title / субтитров | `SmashEgg.message()` | Сообщения о поломке не тонут в чате |
| 5 | **Настройки звука ограничены.** Громкость и питч зашиты, источник всегда MASTER | `Sounds.java:17-18,59` | `sounds.failure.volume/pitch/source` и проигрывание звука nearby-игрокам |

## 2. Ограничения механики (задокументированы, но не закрыты)

- **Кастомные яйца.** Тип берётся из материала (`EggTypes`), поэтому яйцо с изменённым компонентом `entity_type` обходит blacklist. На Paper это читается через компоненты предмета — можно сделать надёжную проверку.
- **Только клик по блоку.** `PlayerInteractEntityEvent`, раздатчики, призыв командами и использование без выбранного блока не обрабатываются (`EggListener.onPlayerUseEgg`). Для настоящего запрета мобов нужен отдельный слушатель `CreatureSpawnEvent`.
- **Нет кулдауна.** Защита только от двойной обработки в одном тике (`blockedThisTick`); спам кликами не ограничен.
- **Нет опции «не расходовать яйцо».** Поведение при неудаче фиксировано: предмет списывается всегда, если игрок не освобождён.
- **Folia не поддерживается** — используется обычный Bukkit scheduler (`SmashEgg.onEnable`, `EggListener.confirmSpawnerChange`).

## 3. Технический долг

- **`event.setCancelled(true)` устарел с 1.14** (`EggListener.java:47,80`). Paper предлагает `setUseItemInHand(Result.DENY)` + `setUseInteractedBlock(Result.DENY)`; поведение эквивалентно, но предупреждения компилятора уйдут.
- **`isInteractable()` слишком широкий** (`EggListener.java:53`): часть блоков без действия на клик тоже считается интерактивной, и проверка пропускается без приседания.
- **Нет `paper-plugin.yml`.** Для Paper-only проекта можно включить изоляцию классов загрузчика и убрать зависимость от `plugin.yml`.
- **Неизвестные ключи конфига молча игнорируются.** Опечатка в `settings.ground-spawn-chance` не обнаруживается; нет `config-version` и миграции схемы.
- **`onEnable`/регистрация команды и слушателя не покрыты тестами.** Все тесты — юнитные на Mockito; интеграционных тестов (например, MockBukkit) нет.
- **Нет релизного пайплайна.** CI собирает и тестирует, но не создаёт GitHub Release и не публикует на Hangar/Modrinth.
- **Нет `CHANGELOG.md`, issue/PR-шаблонов, checkstyle/spotbugs, `.editorconfig`.**

## 4. Организационное

- **В репозитории нет файла `LICENSE`** для самого проекта — упоминается только лицензия Maven Wrapper. Без него плагин формально нельзя ни распространять, ни форкать; нужно выбрать лицензию (MIT или GPLv3 — типичный выбор для Bukkit/Paper-плагинов).
- **Нет описания для площадок** (Hangar/Modrinth/SpigotMC): страницы, скриншоты, список команд для публикации.

## 5. Что уже закрыто в 3.0.0

- Сборка и API переведены с Spigot на Paper (`io.papermc.paper:paper-api`), Adventure берётся из сервера, shade и relocation убраны.
- Звуки переведены на namespaced-ключи (`org.bukkit.Sound` в Paper — интерфейс реестра, `valueOf` больше не существует); старые имена из 2.x принимаются с предупреждением.
- Добавлены отсутствовавшие `.gitignore`, `.mvn/wrapper/maven-wrapper.properties` (без него `./mvnw` не работал) и `.github/workflows/build.yml`, который README описывал, но которого не было в репозитории.

## Предлагаемый порядок работ

1. `LICENSE` + `CHANGELOG.md` (час, разблокирует публикацию).
2. `/smashegg info` и плейсхолдеры в сообщениях (заметно игрокам, дёшево).
3. Per-mob / per-world шансы и whitelist (основная функциональная заявка).
4. Компоненты предмета для кастомных яиц + `CreatureSpawnEvent` как отдельный режим запрета.
5. Частицы, настройки звука, локализация.
6. Folia-поддержка через region scheduler.
